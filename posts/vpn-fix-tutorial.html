Windows 內建 VPN 連不上？L2TP/IPsec 分段診斷與修復實錄

D
Dickens
📅 2026-11-17 📖 12 分鐘閱讀 👁 89 次瀏覽

症狀：輸入帳密後一直「正在連線」→ 點進去看變成「正在中斷連線」→ 最後 Disconnected。而同一組帳密在手機上（行動網路，不是同一個 WiFi）連得上。

💡 這是 Windows 內建 VPN（L2TP/IPsec + PSK）連不上問題的完整診斷與修復筆記，含工具腳本（vpn-preflight.ps1 / vpn-fix.ps1）與一次完整個案的排查方法論。GitHub 原始碼：pkjoe88/vpn-fix

為什麼需要這個

這個症狀最惱人的地方是：設定畫面看起來很正常。VPN 設定存在、帳密也輸入了、沒有任何錯誤訊息，但就是連不上。

而且「重灌系統」沒用——這點最容易被誤判成作業系統壞掉。重灌只是把設定重置回預設的錯法，PSK 和 NAT 穿透鍵都不會跟著回來。

🔍

兩個根因

#根因說明
1 協定對不上 遠端是 L2TP/IPsec + PSK，但電腦 TunnelType=Automatic 會先試不存在的 IKEv2；而 L2TP 格裡設的是憑證 + EAP，PSK 伺服器永遠驗不過
2 缺 NAT 穿透鍵 NAT 後方的 Windows 打 L2TP/IPsec 需要 HKLM:\SYSTEM\CurrentControlSet\Services\PolicyAgent\AssumeUDPEncapsulationContextOnSendRule = 2。新裝 OS 預設就沒有，重灌後消失就是這個原因
🛠

用法：四步修復流程

⚡ 步驟 0 是整個流程最省時間的判斷，跳過它會浪費很多時間在錯誤的方向上。

步驟 0：先確認不是伺服器的問題（30 秒）

拿手機用行動網路（不要用同一個 WiFi）連同一組帳號。

✅ 手機能連

伺服器、帳號、PSK 全部沒問題，問題在這台電腦，繼續往下。

❌ 手機不能連

伺服器端或帳號的問題，不要動電腦設定。

步驟 1：診斷（唯讀）

# 不帶參數：只看現況
.\vpn-preflight.ps1

# 帶目標伺服器：判斷該改哪一筆 + 檢查協定參數
.\vpn-preflight.ps1 -Server 211.72.40.73

步驟 2：修復

# 這台已經有該 VPN 的設定 -> 修改它
.\vpn-fix.ps1 -Server 211.72.40.73 -Apply

# 這台完全沒有 -> 新增一筆
.\vpn-fix.ps1 -Server 211.72.40.73 -Name 'VPN' -PskFile C:\Temp\psk.txt -Apply
⚠️ 預設是 dry run，只印出「將要做什麼」不會動。加 -Apply 才真的執行。

步驟 3：重開機

🔄 這步不做，前面全部白做。腳本不會自動重開。

步驟 4：複驗

.\vpn-preflight.ps1 -Server 211.72.40.73
📦

兩個腳本的分工

腳本會不會改東西用途
vpn-preflight.ps1 不會（純唯讀） 診斷現況、判斷該改哪一筆、列出差異
vpn-fix.ps1 只在 -Apply 時改，而且只改目標那一筆 執行修改或新增
🎯

設計上的兩個關鍵決定

1. 用 ServerAddress 當鍵，不用「第一筆」

VPN profile 的名稱可以任意、重複、無意義。同一台機器上有兩筆不同名稱的 profile 指向同一個伺服器，是完全合法的狀況。

反過來，名稱是唯一的（Add-VpnConnection 撞名會報 WIN32 183），但 ServerAddress 不唯一。

所以「找出該改哪一筆」只能用 ServerAddress。常見的 Select-Object -First 1 只在剛好只有一筆 profile 時才安全，換台機器就會改錯。

2. 四種情境，沒有一種會碰到無關的 profile

情況動作
1 筆指向目標 IP改它
2 筆以上指向目標 IP停下報錯 🛑
0 筆指向目標 IP，但名稱被占用停下報錯 🛑
0 筆指向目標 IP，名稱也沒被占用新增
🛑 第 2 種會刻意停下來：重複 profile 是真的會發生（用不同方式建過同一台伺服器）。挑錯一筆會改壞還在正常使用的那個，而且事後不會有感覺。寧可什麼都不做。
🕳

已知陷阱（踩過的坑）

Get-VpnConnection 讀不回 PSK

不要用 $c.L2tpPsk 判斷 PSK 有沒有設定——它幾乎都回空值。要確認請直接看：

%AppData%\Microsoft\Network\Connections\Pbk\rasphone.pbk

Set-VpnConnection 沒有 -UserConnection 參數

只有 -AllUserConnection。所以 profile 有「全機層」和「使用者層」兩種，修改時必須沿用原本的層級，否則會報「找不到連線」——但 profile 明明存在，只是層級錯，錯誤訊息會誤導。

scope 在建立時就定了，之後改不了

要把使用者層改成全機層（或反過來），只能 Remove-VpnConnection 再 Add-VpnConnection。混合使用不會壞，但會造成「設定看得到、某個使用者連不上」的困惑情況。

有些 profile 只存在於 rasphone.pbk

被第三方工具寫入的、或舊版建立的設定，Get-VpnConnection 看不到，指令也改不到。vpn-preflight.ps1 會交叉比對並列出來。

rasphone.pbk 有兩個，依 scope 分開存放：

全機層：C:\ProgramData\Microsoft\Network\Connections\Pbk\rasphone.pbk
使用者層：%AppData%\Microsoft\Network\Connections\Pbk\rasphone.pbk
⚠️ 實測：本機的 profile 是全機層，只有 C:\ProgramData 那份存在，%AppData% 那份不存在。只看 AppData 會誤判為「沒有 profile」。

錯誤訊息是英文

Add-VpnConnection 撞名時回報 This VPN connection has already been created.（英文），即使系統是中文語系。這不是錯誤。

⚙️

執行環境需求

  • Windows 10 / 11（Add-VpnConnection 需要 Windows 8 以上）
  • PowerShell 5.1 以上
  • vpn-fix.ps1 需要系統管理員權限；vpn-preflight.ps1 不需要
  • 本專案的 .ps1 以 UTF-8 with BOM 儲存——PowerShell 5.1 讀無 BOM 的 UTF-8 會用系統 ANSI 碼頁解讀，中文會變亂碼並導致語法錯誤
📐

範圍界定

本專案只處理 Windows 內建 VPN 的 profile 設定。

不處理：防火牆規則、路由器／ISP 的 IPsec passthrough、VPN 伺服器端設定、第三方 VPN 軟體衝突。若換環境後仍連不上，再依下方附錄的出局順序逐項排除。

📋

附錄：原始個案排查（2026-09-29 結案）

以下是當時的實際排查紀錄。八步出局順序完全不依賴特定機器，換環境後照順序走：

#排查項目結果
1伺服器沒死ping 60.249.133.148 5ms 零遺失，TCP 1723／443 有開
2看 RasClient logVpnStrategy=IKEv2,SSTP,PPTP then L2TP，實際用 WAN Miniport (IKEv2) 去撥，通了又 requires attention 斷掉
3網卡無罪對閘道 20/20 零遺失平均 3ms
4本地路由器出局Features → Firewall → Advanced 的 IPSec/PPTP 全開，無防火牆規則
5Windows 防火牆出局家用網屬私人/公用，兩個 profile 都是關的
6家裡固網出局手機開熱點給電腦撥，一樣掛
7遠端 Router 出局手機 L2TP 連得上，帳密＋伺服器正常
8剩下：電腦 VPN 設定＋NAT 穿透鍵PolicyAgent 下無 AssumeUDPEncapsulationContextOnSendRule ← 真兇
📝 log 位置：C:\Windows\System32\LogFiles\RasClient\（連一次失敗的連線才會產生檔案）。

.reg 變通做法

不想用指令、想走登錄編輯器時（.reg 編碼用 UTF-16 LE 或 ANSI，勿用 UTF-8）：

Windows Registry Editor Version 5.00

[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\PolicyAgent]
"AssumeUDPEncapsulationContextOnSendRule"=dword:00000002

附帶：同場兩條無害 log

排查時會看到、與 VPN 無關的雜訊，看到不用追：

  • WORKGROUP <1D> 登錄失敗（NetBT 4321）— 區網上另一台機搶了主瀏覽器角色。不影響上網與 VPN
  • DCOM {A463FCB9…} smartscreen.exe 0x80070002— SmartScreen 被設成 Off 之後，DCOM 照樣呼叫但叫不起來。故意關的就忽略
🎓

教訓

  1. 手機同帳號能連 = 伺服器沒事——往電腦設定和中間 NAT 查，不要浪費時間重灌
  2. PSK 不要經 console 貼上——右鍵貼進 PowerShell 會被吃掉變成空字串。走暫存檔轉入，用完即刪
  3. 重灌不是解法——只會把設定重置回預設的錯法
  4. 設定畫面正常不代表協定對——Automatic 這種值在 UI 上看不出問題，只有讀 log 才會發現它先試了不存在的協定
