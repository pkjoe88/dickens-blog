devil-server 從 Ubuntu 24.04 升上 26.04.1 LTS：升級過程記錄

D
Dickens
📅 2026-11-26 📖 6 分鐘閱讀 👁 1 次瀏覽

家裡的 Linux 主機 devil-server（Ubuntu 24.04）今天升上 26.04.1 LTS。26.04 是今年四月出的 LTS，代號 Resolute Raccoon，九月底才開放 24.04 直接升，支援到 2031 年。博客就跑在這台上（Docker 裡的 WordPress，前面有 nginx 和 Cloudflare Tunnel），所以升級前先備份，升完再把軟體源一個一個修好。以下是完整過程。

第一步：備份

先把 WordPress 停下來再打包，免得備到一半寫入的資料庫：

cd /data/appdata/wordpress && sudo docker compose stop
sudo tar -czf /data/backup/ubuntu2604-upgrade-20261126/wordpress-appdata.tar.gz -C /data/appdata wordpress
sudo tar -czf /data/backup/ubuntu2604-upgrade-20261126/etc-backup.tar.gz /etc/nginx/sites-available/dickens.cc.cd /etc/cloudflared /etc/apt/sources.list.d
sudo docker compose start

備份在 /data/backup/ubuntu2604-upgrade-20261126/：WordPress 資料 39M，設定 2.2K。容器停了又起來，博客只斷了一兩分鐘。空間也夠，根目錄還有 874G。

第二步：把 24.04 更新到最新

sudo apt update && sudo apt dist-upgrade -o APT::Get::Always-Include-Phased-Updates=true -y
sudo apt install -y update-manager-core
ls /run/reboot-required && echo "需要重開機" || echo "不用重開機"

結果是 0 個待升級，也不用重開機，24.04 已經是最新了。

第三步：確認有提供 26.04.1

do-release-upgrade -c

回「有新版『26.04.1 LTS』提供」，可以升。

第四步：正式升級

sudo do-release-upgrade

中途會停幾次等你回。套件的更新說明（wireplumber、git 那些）按 q 跳過就好，不用看完。

其中一個一定要選對：/etc/samba/smb.conf 問要新版還是保留本地版，選「keep the local version currently installed」。Samba 的分享設定（data、appdata）和 interfaces 那行都是自己改的，選新版會整個被洗掉，備份分享就沒了。

最後問刪舊套件、重開機，都按 y。整個過程大概半小時，博客和遠端桌面中途會斷。如果畫面斷了不用慌，升級是在 screen 裡跑的，重連進來再跑一次 sudo do-release-upgrade 就會接回去繼續。

小插曲：apt update 沒加 sudo

裝完跑 apt update 報錯，鎖檔打不開、權限被拒。不是升級壞掉，是少打了 sudo，apt 要寫系統目錄一定要 root 權限。sudo apt update 就通了，全部都是最新。

第五步：修軟體源

升級會把第三方軟體源停用。這台有四個：Docker、Tailscale 的原檔被改名成 .disabled，還停在 noble；Chrome 和 Chrome 遠端桌面被加了 Enabled: no。Docker 和 Tailscale 兩家都有出 26.04（resolute）的套件，先查過才改；Chrome 兩家是 stable 版次，不用改代號。

Docker、Tailscale 重建成 resolute：

sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<'EOF'
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: resolute
Components: stable
Architectures: amd64
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo tee /etc/apt/sources.list.d/tailscale.sources > /dev/null <<'EOF'
Types: deb
URIs: https://pkgs.tailscale.com/stable/ubuntu
Suites: resolute
Components: main
Signed-By: /usr/share/keyrings/tailscale-archive-keyring.gpg
EOF

Chrome 兩家把 Enabled: no 刪掉：

sudo sed -i '/^Enabled: no$/d' /etc/apt/sources.list.d/google-chrome.sources /etc/apt/sources.list.d/chrome-remote-desktop.sources

再更新一次，把四家的套件升到 26.04 版：

sudo apt update && sudo apt full-upgrade -y

驗證

lsb_release -a
sudo docker ps --format '{{.Names}} {{.Status}}'
tailscale status

lsb_release 是 Ubuntu 26.04.1 LTS，三個容器（WordPress、資料庫、Portainer）重啟後都在跑，Tailscale 也連著。博客測了回 200，標題正常。

備份先留著，過幾天確定沒問題再清。

「升級最花時間的不是下載，是升完把軟體源一個一個修回來。」
